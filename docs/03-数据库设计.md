# 03 · 数据库设计

> V1.0 · 2026-10-16 · P0-MVP 建 17 张表；P1/P2 预留表见第 4 节

## 0. 命名规约

- 表名 / 字段名：snake_case；主键统一 `id BIGINT`；外键 `xxx_id`；时间 `*_at DATETIME`；JSON 列 `*_json`。
- **金额一律用分（BIGINT）**，列名 `*_cents`；禁止 float/double 存钱。
- JSON 列：生产 MySQL 用 `JSON` 类型；开发 SQLite 用 `TEXT` + SQLAlchemy `TypeDecorator` 自动序列化（模型层无感）。
- 枚举用 `String` + 应用层常量校验（不用 DB ENUM，便于演进）。
- 所有表带 `created_at`；变更频繁的表带 `updated_at`。

## 6. 设计要点

1. **能力分 = 快照 + 事件溯源**：可回溯任意时刻成长曲线，加权规则在服务层实现，不写死在库里。
2. **作品版本链**：`parent_id` 串版本，`ai_declare_json` 记录每版 AI 参与度，支撑"初终稿差异比对"教学伦理设计。
3. **文件与数据分离**：库内只存 `storage_key`，文件走 Local/MinIO。
4. **工单状态机**：draft → pending_review → published → bidding → awarded → closed；P0 不做合同/验收/结算表，验收结果先记 `meta_json`。
5. **配额与成本**：`agent_call_logs` 同时服务配额统计（按 user 按日）与成本看板（按 agent_type 汇总）。
