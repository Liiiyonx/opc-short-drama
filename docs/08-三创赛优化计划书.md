# 08 · 三创赛优化与冲奖计划书

> 版本：V1.0  
> 日期：2026-11-21  
> 适用目标：全国大学生电子商务“创新、创意及创业”挑战赛及同类创新创业竞赛  
> 一句话定位：把短剧出海全流程变成一套可教学、可审计、可交付的 AI 生产系统，而不是一个只会生成文本的演示页。

---

## 0. 一页结论

### 0.1 当前判断

项目已经越过“能不能做出来”的阶段，当前主要矛盾不是功能数量，而是以下三项：

1. **现场确定性不足**：真实 AI、Redis、ffmpeg、worker、端口和演示数据都可能成为单点故障。
2. **第一印象不够强**：核心流程可以跑通，但最新成片仍是 2.592 秒、720×1280、约 13KB 的纯色占位画面，无法支撑“短剧出海”的视觉叙事。
3. **商业与育人证据不足**：目前能证明“系统闭环”，还不能充分证明“学生真的成长、企业真的愿意用、平台真的可复制”。

因此，冲奖策略应是：

> **稳定演示 × 高质量样片 × 可核验证据 × 清晰商业模式**

而不是继续堆叠更多智能体或更多菜单。

### 0.2 内部准备度

以下为项目内部备战评估，不是赛事官方评分：

| 维度 | 当前状态 | 判断 |
|---|---:|---|
| 十智能体与三端业务闭环 | 9/10 | 已达到优秀竞赛项目的内容厚度 |
| 后端工程与自动化测试 | 9/10 | 55 个测试全过，基础扎实 |
| 前端桌面端完成度 | 7/10 | 主流程可演示，细节仍需打磨 |
| 移动端可用性 | 4/10 | 学生工作台存在明显拥挤、表格不可读问题 |
| 成片视觉质量 | 3/10 | 当前占位色块会严重削弱评委第一印象 |
| 现场演示可靠性 | 5/10 | 依赖外部网络、Redis、ffmpeg、脚本环境 |
| 安全与权限边界 | 5/10 | 存在公开注册教师/企业角色、演示密码常驻等风险 |
| 商业验证证据 | 3/10 | 尚缺真实试点、企业意向、验收单和收入凭证 |
| 可观测与质量评测 | 5/10 | 有调用日志和成本记录，但缺 Trace、评测集与告警 |
| 竞赛材料完整度 | 5/10 | 有文档和脚本，缺成套证据链、展示视频和答辩版材料 |

**结论：当前项目是“强原型、强工程、弱展示证据”。完成本计划 P0 后，才具备稳定的国赛答辩基础。**

### 0.3 三档目标

| 档位 | 时间 | 必须达成的结果 |
|---|---|---|
| 保底档 | 7 天 | 三套演示模式可用；断网也能完整走通；移动端不崩；无 P0 故障 |
| 冲奖档 | 4 周 | 高质量样片、角色权限、自动刷新、可重复 E2E、基础可观测、商业数据模板 |
| 冠军档 | 8 周 | 真实试点证据、企业意向与验收、评测集、A/B 实验、可复制部署包 |

### 0.4 五个不可妥协的决策

1. **先修可靠性，再扩功能**。P0 期间冻结新增智能体。
2. **现场主流程不等待真实大模型**。使用确定性缓存模式，真实模式只用于局部展示或问答。
3. **所有演示画面必须有真实视觉资产**。禁止用纯色占位图承担主演示。
4. **所有商业数据必须有证据来源**。没有凭证的试点数、订单数、收入不得进入答辩口径。
5. **演示机与开发机分离**。冻结版本、固定浏览器、固定端口、固定数据快照。

## 1. 现状诊断

### 1.1 已被验证的优势

- 后端全量测试通过：`55 passed`。
- 前端生产构建通过，主包 JS gzip 约 96KB。
- 学生、教师、企业、管理员四角色桌面端均可登录，无控制台错误和横向滚动。
- 学生六步创作工坊在桌面端和移动端均可加载。
- 剧本、分镜、翻译、配音、字幕、成片、发布参数、AI 声明、任务提交、Rubric 批改、能力更新的核心 API 链路已跑通。
- 已有 JWT、限流、配额、调用日志、成本估算、版本链、Range 文件流、健康检查和备份脚本。
- 已有教师任务、企业工单、投标定标、作品集分享、能力预警、AI 备课等教学与产业闭环。

这些能力说明项目不是“概念 PPT”，已经具备真实产品骨架。

### 1.3 P0 级代码风险

| 风险 | 位置 | 影响 | 必修动作 |
|---|---|---|---|
| 健康检查降级仍返回 HTTP 200 | `backend/app/main.py` | Compose 会把故障实例判为健康 | DB 或 Redis 故障时 `/readyz` 返回 503 |
| 公开注册可选教师/企业角色 | `backend/app/schemas/auth.py`、`backend/app/api/v1/auth.py` | 任意用户可自行获得高权限身份 | 仅学生自助注册；教师/企业走申请与审核 |
| refresh token 未使用 | `frontend/src/api/index.js`、`frontend/src/stores/user.js` | access token 过期后直接跳登录 | 401 自动刷新并重放请求 |
| 登录页永久展示四个演示密码 | `frontend/src/views/Login.vue` | 生产环境泄露演示账号 | 仅显式 Demo 模式展示 |
| 一键演示脚本依赖 Bash 工具链 | `demo_up.sh`、`demo_down.sh` | Windows 现场不稳定 | 补 PowerShell 启动器与依赖闸门 |
| 数据面镜像未完全固定版本 | `docker-compose.yml` | 拉取新版本可能引入不可复现问题 | 固定镜像 tag 或 digest |
| worker 无独立健康检查 | `docker-compose.yml` | API 健康但异步任务可能已失效 | 增加心跳、队列和 worker 就绪探针 |
| E2E 依赖共享预置数据 | `backend/scripts/e2e_api_test.py` | 每次运行结果不可重复 | 独立夹具、自建数据、自动清场 |
| 演示文案与真实能力不一致 | README、演示脚本、健康检查注释 | 评委追问时易失去可信度 | 建立“能力口径表”并统一修订 |

### 1.4 真正的产品差距

当前最值得补的不是“更多 Agent”，而是以下四项用户可感知价值：

1. 从文字镜头表升级为能直接看的分镜图、角色设定和动态预览。
2. 从占位成片升级为可直接用于答辩展示的 15-30 秒高质量样片。
3. 从“系统有日志”升级为“每一步为什么这样、花了多少钱、质量如何”的可解释闭环。
4. 从“流程上能发工单”升级为“有人愿意发、学生能交付、教师能验收”的证据闭环。

## 2. 三创赛叙事设计

### 2.1 项目问题

短剧出海团队需要同时解决选题、本地化、配音、剪辑、平台运营和跨文化合规。传统培养方式把商务英语、电子商务、视频制作拆成不同课程，学生难以在校期间完成一个真正可交付的海外内容项目。

### 2.2 项目方案

平台把完整生产流程拆成十个可审计的智能体，并由学生、教师、企业三方共同完成：

- 学生负责创意选择、分镜判断、人工修订和最终交付。
- 教师负责任务设计、过程评价、能力诊断和合规审核。
- 企业负责真实需求、项目验收和人才遴选。
- AI 负责加速重复劳动，但不替代学生的判断、表达和责任。

### 2.3 “三创”表达

| 维度 | 答辩表达 | 可验证证据 |
|---|---|---|
| 创新 | 将多智能体生产链、成本计量、人工修订和能力画像放在同一工作流中 | 调用日志、成本记录、版本链、Rubric、能力快照 |
| 创意 | 用短剧出海作为真实项目载体，把商务英语与电商能力转化为可交付作品 | 多语种剧本、分镜、字幕、发布参数、作品集 |
| 创业 | 面向高校、MCN、品牌和产业中心提供 B2B SaaS 与私有化部署 | 企业意向书、工单、验收单、试点协议、报价实验 |
| 社会价值 | 降低学生进入数字内容产业的门槛，支持县域产业带和传统文化内容出海 | 课程试点、学生成长前后测、真实作品传播数据 |

### 2.4 核心壁垒

1. **流程壁垒**：十智能体不是散装工具，而是带状态、版本、失败恢复和成本记录的生产链。
2. **教育壁垒**：AI 使用声明、初终稿差异度、Rubric 能力映射，构成“可教、可评、可解释”的教学治理层。
3. **产业壁垒**：真实工单、教师审核、企业验收和能力匹配形成双边网络。
4. **数据壁垒**：Prompt 版本、市场偏好、学生修正、企业验收和结果指标可以沉淀为评测集。

### 2.5 对外口径边界

| 不能说 | 应改为 | 原因 |
|---|---|---|
| “全程离线” | “完成依赖打包后，可无公网运行核心链路” | 当前仍依赖 Redis 和 ffmpeg |
| “一键发布四平台” | “生成多平台发布参数包，半自动发布” | 当前未接官方发布 API |
| “已经实现商业收入” | “已跑通意向制交易闭环，收入数据待试点核验” | 没有凭证不能宣称 |
| “AI 全自动制作短剧” | “AI 辅助完成全流程，学生负责判断与终审” | 符合产品实际和 AI 伦理 |
| “支持 50 并发” | “目标支持 50 并发，待压测报告验证” | 当前没有正式压测证据 |
| “八智能体” | “十智能体” | 文档元数据存在旧口径 |

## 3. 功能优化路线

### 3.1 优先级原则

| 优先级 | 判定标准 | 处理方式 |
|---|---|---|
| P0 | 不修就会当场失败、产生权限风险或严重削弱第一印象 | 7 天内全部完成 |
| P1 | 能形成明显差异化或支撑商业验证 | 4 周内完成 |
| P2 | 增强想象空间，但不影响首次答辩 | 8 周后逐步推进 |

### 3.2 P0 必做清单

#### P0-01 健康检查与依赖闸门

目标：

- 新增 `/livez`：仅表示进程存活。
- `/readyz`：DB、Redis 必须可用，否则返回 503。
- `/health`：返回 DB、Redis、worker 心跳、存储、ffmpeg、当前 AI 模式。
- 前端在缓存/离线模式下显示明确的“确定性演示模式”标识，不做静默降级。

验收：

- 停止 Redis 后 `/readyz` 在 3 秒内返回 503。
- worker 停止后 30 秒内业务探针失败，并给出可读告警。
- Compose 不会把降级 API 判为健康。

#### P0-02 注册与角色权限

目标：

- `/auth/register` 只允许学生自助注册。
- 教师、企业改为“提交申请 + 管理员审核”。
- 演示账号由种子脚本管理，生产环境不可见。

验收：

- 学生调用注册无法指定教师或企业角色。
- 未审核教师/企业账号不能访问对应业务接口。
- 登录页在非 Demo 环境不展示任何密码。

#### P0-03 Token 自动刷新

目标：

- Axios 401 时只触发一次 refresh。
- 并发 401 共享同一个刷新 Promise。
- 刷新失败才清理登录态；刷新成功自动重放原请求。

验收：

- access token 过期后连续操作不跳登录。
- 10 个并发请求同时遇到 401 时，只发送一次 refresh。

#### P0-04 Demo 模式隔离

目标：

- 增加显式环境变量，例如 `VITE_DEMO_MODE=true`。
- Demo 模式显示演示账号、示例数据和模式横幅。
- 生产模式隐藏演示账号、重置按钮和测试入口。

验收：

- 生产构建中源码与页面均不出现四个演示密码。
- Demo 构建可以一键填充账号，并有清楚的“演示数据”提示。

#### P0-05 Windows 一键演示

目标：

- 新增 `scripts/demo.ps1` 和 `scripts/demo-down.ps1`。
- 检查端口、Python、Node、Redis、ffmpeg、磁盘空间、数据库、队列和 provider。
- 任一必需依赖失败时拒绝打开演示页，而不是“带病继续”。
- 提供 `start`、`rehearse`、`reset`、`snapshot`、`status`、`down` 子命令。

推荐包结构：

```text
demo_runtime/
├── app/                  # 已构建前端与后端代码
├── assets/               # 已授权图片、音频、字体
├── scenarios/            # 确定性场景与视频
├── runtime/              # Redis / ffmpeg / 浏览器补丁
├── snapshots/            # 数据库与存储快照
├── checksums.sha256
└── manifest.json
```

验收：

- 新 Windows 演示机在断网状态下，一次命令启动成功。
- 冷启动 90 秒内进入可演示状态。
- 重复启动不会重复插入数据、不会占用旧端口。

#### P0-06 确定性数据与可重复 E2E

目标：

- 每次 E2E 创建独立用户、课程、任务、作品与工单。
- 不依赖数据库中存在若干待审核工单。
- 完成后自动清理，或使用一次性测试数据库。
- 输出固定 UTF-8，兼容 Windows。
- Playwright 覆盖学生、教师、企业、管理员和移动端。

验收：

- 连续运行 10 次 E2E，通过率 100%。
- E2E 不依赖预置数据、不依赖执行顺序。
- 一次失败能保留 trace、截图、视频和后端请求 ID。

#### P0-07 移动端响应式

目标：

- `el-col` 使用 `xs/sm/md/lg` 断点。
- 任务表在移动端改为卡片列表或允许横向滚动，不能压扁列。
- 顶栏拆分为品牌行和账号行。
- 能力条保留名称、分数、进度和预警文字。
- 所有触控目标不小于 44px。

验收：

- 390×844、414×896、768×1024 三档无重叠、无横向页面滚动。
- 关键按钮不被遮挡，最长中英文文本不溢出。
- 移动端完成“登录 → 工作台 → 作品 → 工坊”路径。

#### P0-08 高质量视觉样片

目标：

- 至少准备 3 组成片：北美逆袭、东南亚电商、文化出海。
- 每组包含角色设定、场景图、6-10 张分镜图、配音、字幕、BGM 和成片。
- 演示成片时长 15-30 秒，1080×1920，画面不得出现纯色占位块。
- 每张素材记录来源、许可证、生成模型、Prompt 和使用范围。

验收：

- 首帧不是空镜头或色块。
- 前 3 秒有明确人物、冲突或商品卖点。
- 字幕不遮挡人脸和平台安全区。
- 音频响度统一，无爆音、无突变、无未授权音乐。

#### P0-09 部署可复现

目标：

- MinIO、MySQL、Redis、Nginx 和运行镜像固定版本或 digest。
- worker 增加健康检查与心跳。
- CI 增加容器启动验证和依赖漏洞扫描。
- README 中的启动方式以 PowerShell 为主，Bash 作为次要方式。

验收：

- `docker compose up --wait` 一次成功。
- 删除缓存后重建仍得到同一版本。
- 关键镜像构建可追溯到 Git commit。

#### P0-10 基础可观测性

目标：

- 请求 ID 贯穿前端提示、API 日志和智能体调用。
- 记录 prompt 版本、provider、model、tokens、耗时、成本、错误类型。
- 增加 worker 心跳、队列积压、任务超时和失败率。
- 错误页面提供可复制的 request ID，不向用户暴露堆栈。

验收：

- 任一次失败能在 2 分钟内定位到请求、智能体、任务和上游响应。
- 教师用量看板之外，管理员可查看系统级错误与队列状态。

#### P0-11 文案与元数据统一

目标：

- 统一为“十智能体”。
- 后端版本从 `0.1.0` 升级到与发布版本一致。
- 删除“降级仍 200 便于编排不抖动”这类与当前目标冲突的注释。
- 演示脚本区分真实、缓存、离线三种模式。

验收：

- `README`、OpenAPI、登录页、演示脚本、PPT 和答辩稿口径一致。
- 搜索不到“八智能体”“全程离线”“一键发布”等误导表述。

#### P0-12 备份、快照与回滚

目标：

- 演示前保存 SQLite/MySQL 数据库和对象存储快照。
- 一键恢复到“首次进入即可演示”的干净状态。
- 失败后 60 秒内回滚，不进后台排障。

验收：

- 故意破坏演示数据后，一条命令恢复。
- 快照校验和通过，恢复后关键页面自动冒烟。

### 3.3 P1 差异化功能

| 功能 | 参考方向 | 产品价值 | 验收指标 |
|---|---|---|---|
| 角色设定库 / Character Bible | Toonflow 的角色与场景资产 | 保证多镜头人物一致性 | 同一角色 6 镜头可识别人物特征 |
| 分镜图生成与替换 | ComfyUI、Toonflow | 从文字镜头表升级为视觉分镜 | 一键生成、单镜重绘、人工替换 |
| 导演模式 | MoneyPrinterTurbo | 用户可调节镜头时长、转场、BGM、字幕样式 | 10 分钟内完成一条可看样片 |
| 任务时间线与自动保存 | 成熟 SaaS | 长任务不怕刷新、断线或误关页面 | 刷新后恢复步骤与表单 |
| Prompt 版本与评测中心 | Langfuse | 可比较不同 Prompt 的质量和成本 | 30 条黄金样例、按月回归 |
| Agent 调试台 | Dify、Coze Studio | 教师/管理员可观察输入输出 | 支持重放、对比、禁用的 Prompt |
| 企业验收工作流 | 同行业项目 | 从“中标”走到“交付通过” | 里程碑、交付物、意见、验收单 |
| 课程与班级数据看板 | Open WebUI 的易用性 | 教师按班级看进度、风险和产出 | 班级完成率、预警、成本一屏可见 |

### 3.4 P2 想象空间

- 可视化 Agent 编排画布：不建议在答辩前重做核心流程，可先做只读拓扑与调试视图。
- 半自动发布：接入官方 API 前继续使用发布参数包。
- 真实视频生成：通过独立 provider 接入，不允许绑定单一高价模型。
- 多租户与私有化交付：面向外校和产业中心复制。
- CosyVoice / 火山 TTS：以音色稳定性和授权清晰度为前提。

## 4. 成片质量升级方案

### 4.1 当前问题

当前 `backend/app/agents/compose_agent.py` 在没有上传图片时，会调用 `placeholder_png` 生成纯色画面。这个设计适合验证链路，不适合承担主演示。

### 4.2 新流水线

```text
剧本
  → 角色卡 / 场景卡
  → 分镜 JSON
  → 分镜图生成或素材检索
  → 人工选图 / 重绘 / 排序
  → 配音与字幕
  → 动态预览
  → 成片质检
  → 发布参数与数据复盘
```

### 4.3 分镜数据结构建议

在保留现有字段的基础上扩展：

```json
{
  "shot_no": 1,
  "scene_id": "office_01",
  "character_ids": ["lin_01", "boss_01"],
  "shot_size": "medium",
  "camera_move": "push_in",
  "duration_sec": 3.2,
  "visual_prompt": "...",
  "image_key": "works/12/storyboard/xxx.webp",
  "transition": "fade",
  "dialogue": ["..."],
  "asset_license": "generated",
  "quality_status": "approved"
}
```

### 4.4 角色一致性

每个项目建立角色卡：

- 姓名、年龄、性别、体型、发型、服装、主色。
- 固定参考图 1-3 张。
- 英文外观 Prompt。
- 禁止漂移特征。
- 生成模型、seed 和版本。

验收时至少检查：

- 同一角色 6 个镜头是否仍可识别为同一人。
- 服装主色和关键道具是否连续。
- 场景空间关系是否前后矛盾。

### 4.5 成片技术标准

| 项 | 展示版标准 |
|---|---|
| 画幅 | 1080×1920，9:16 |
| 编码 | H.264 / AAC |
| 时长 | 15-30 秒 |
| 首帧 | 有人物、商品或冲突信息 |
| 镜头 | 至少 6 个不同画面 |
| 字幕 | 安全区内、对比清晰、无遮挡 |
| 音频 | 人声清晰，BGM 自动压低 |
| 节奏 | 前 3 秒出现钩子 |
| 版权 | 每项素材有许可或生成记录 |

### 4.6 演示素材包

```text
│   ├── character-bible.json

```

### 4.7 质检闸门

成片发布前自动检查：

- 不得存在纯色占位帧。
- 不得黑屏超过 0.3 秒。
- 字幕不得超出画幅安全区。
- 音轨不得削波。

- 素材许可证与 AI 声明齐全。

## 5. 现场零故障方案

### 5.1 可靠性目标

> 一套命令启动，四种健康闸门，三种演示模式，两台设备，一键回滚。

### 5.2 三种演示模式

| 模式 | 用途 | 行为 |
|---|---|---|
| Live | 展示真实 AI 能力 | 请求真实模型和 TTS，允许等待 |
| Cached | 主答辩模式 | 使用确定性场景缓存，完整经过 API、队列、数据库和前端 |
| Offline | 断网兜底 | SQLite、本地存储、内置 Redis、内置 ffmpeg、本地素材 |

Cached 和 Offline 必须显示明显标识，不能伪装成实时 AI。

### 5.3 四道健康闸门

1. **进程闸门**：前端、API、worker 均存活。
2. **依赖闸门**：DB、Redis、存储、ffmpeg、浏览器可用。
3. **数据闸门**：演示用户、作品、任务、工单和快照校验正确。
4. **业务闸门**：自动执行登录、打开工坊、加载视频、生成发布参数包和读取能力数据。

任何一道闸门失败，不进入正式演示。

### 5.4 三套环境

| 环境 | 角色 | 要求 |
|---|---|---|
| 开发环境 | 日常迭代 | 可用真实外部服务 |
| 彩排环境 | 与现场同构 | 固定依赖、固定快照、固定浏览器 |
| 演示环境 | 冻结版本 | 不升级、不调试、不安装新依赖 |

### 5.5 演示机标准

- 独立 Windows 用户，关闭系统更新和通知。
- 固定版 Chrome/Edge，禁用自动更新。
- 使用固定 `127.0.0.1` 地址与固定端口。
- 清理浏览器扩展、剪贴板、历史和自动填充。
- 电源常连，关闭睡眠和屏保。
- 主用一台，备用一台，配置相同快照。
- 演示包放在本地 SSD，另备 U 盘和云端离线压缩包。

### 5.6 风险注入彩排

正式答辩前至少完成以下演练：

1. 拔掉外网。
2. 杀死 worker。
3. 重启 Redis。
4. 模拟 LLM 超时。
5. 重复点击生成按钮。
6. 刷新生成中的页面。
7. 使用错误密码登录。
8. 恢复数据库快照。
9. 从备用机启动同一快照。
10. 播放预录演示视频。

每一项都必须有明确恢复步骤，且不得进入命令行排障。

### 5.7 时间节点清单

| 时间 | 动作 |
|---|---|
| T-7 天 | 冻结 P0 范围，构建演示包，开始每日彩排 |
| T-3 天 | 停止非关键改动，只允许修复彩排发现的 P0 |
| T-1 天 | 备份两份演示机、更新录屏、验证断网启动 |
| T-30 分钟 | 启动主备机，执行四道闸门，关闭通知 |
| T-5 分钟 | 登录固定账号，打开演示页，播放 3 秒样片确认声音 |
| 现场 | 主流程只用 Cached；真实能力仅在问答或局部演示中触发 |

### 5.8 兜底材料

- 15 分钟完整录屏。
- 8 分钟精简版。
- 3 分钟无声自动播放版。
- 关键页面截图 PDF。
- 一条本地 MP4 成片。
- 一份离线答辩 PPT。

## 7. AI 可观测与质量评测

### 7.1 从“调用日志”升级为“生产证据”

现有 `agent_call_logs` 已记录 provider、model、tokens、成本、状态和耗时，下一步补：

- `trace_id`：一次用户操作贯穿同步调用、异步任务和文件生成。
- `prompt_version`：明确 Prompt 文件和版本。
- `input_hash`：用于缓存命中和重放。
- `quality_score`：教师评分、自动规则分或人工验收分。
- `user_feedback`：有用/无用、修改原因。
- `error_category`：超时、限流、格式错误、内容拒绝、内部异常。

### 7.2 黄金评测集

建议建立 30 条固定样例：

- 5 个目标市场。
- 3-5 个题材。
- 中、英、日、韩、西、阿等语言组合。
- 包含正常、边界、敏感和超长输入。

每条记录：

- 输入。
- 人工基准输出。
- 结构化契约通过率。
- 语言与文化评分。
- 角色一致性评分。
- 成本和耗时。
- 失败原因。

### 7.3 评测指标

| 指标 | 目标 |
|---|---:|
| JSON 契约通过率 | ≥ 99% |
| 核心链路成功率 | ≥ 99% |
| 本地非 AI 接口 P95 | < 500ms |
| 缓存主流程启动 | < 90 秒 |
| 单次剧本生成 P95 | 依模型设定阈值并持续回归 |
| 字幕时间轴误差 | 人工抽检平均 < 300ms |
| 角色一致性人工通过率 | ≥ 80% |
| 教师可接受交付率 | ≥ 80% |
| 物料许可证覆盖率 | 100% |

### 7.4 三类看板

1. **业务看板**：课程、学生、作品、任务、工单、验收。
2. **AI 看板**：调用量、成本、延迟、失败、Prompt 版本、质量分。
3. **可靠性看板**：API、worker、队列、Redis、存储、磁盘、错误率。

### 7.5 实验能力

- Prompt A/B：同一输入比较两个版本的结构、质量和成本。
- 模型 A/B：比较 DeepSeek、备用模型和本地模型。
- 市场 A/B：同一剧本在不同国家/平台的标题、钩子和节奏表现。
- 教学 A/B：有 AI 声明和差异反馈的班级是否产生更高人工修订质量。

## 8. 商业化与产教融合

### 8.1 客户与价值

| 客户 | 痛点 | 平台价值 | 付费方 |
|---|---|---|---|
| 高校电商/商英专业 | 课程分散、缺真实项目、难评价 AI 使用 | 课程包、任务流、Rubric、能力画像 | 学校/学院 |
| MCN/出海内容团队 | 产能低、翻译与本地化慢、成本不透明 | 标准生产链、项目管理、成本控制 | 企业 |
| 品牌/产业带商家 | 缺多语种短视频素材 | 商品短视频、多市场版本、发布参数 | 品牌/服务商 |
| OPC/产业中心 | 缺统一工具与人才供给 | 实训、接单、人才匹配、运营看板 | 中心/政府项目 |

### 8.2 收入模式

建议采用组合模式，不走“平台托管赏金”：

1. 高校课程年度授权。
2. 企业项目制服务费。
3. 私有化部署与实施费。
4. 教师培训、课程共建和认证服务。
5. 产业中心平台运营服务费。

### 8.3 单位经济模型

不要直接宣称固定毛利，必须按真实项目核算：

```text
单条成片毛利
= 企业/课程分摊收入
- LLM 成本
- TTS 成本
- 图像/视频生成成本
- 渲染与存储成本
- 教师/运营人工成本
- 获客与售后成本
```

必须采集：

| 字段 | 单位 | 说明 |
|---|---|---|
| 成片时长 | 秒 | 分母统一 |
| AI 直接成本 | 元 | 从调用日志汇总 |
| 渲染成本 | 元/分钟 | 按机器折旧或云资源折算 |
| 人工审核时长 | 分钟 | 教师/导演/运营 |
| 折合人工成本 | 元 | 按角色小时成本 |
| 首次交付周期 | 小时 | 从需求到首版 |
| 修改轮次 | 次 | 反映流程质量 |
| 验收通过率 | % | 反映真实价值 |
| 单条毛利 | 元 | 必须带凭证 |

### 8.4 试点设计

最小可信试点：4 周。

- 1 门真实课程。
- 30 名左右学生。
- 2 名教师。
- 3 个企业工单。
- 3-5 条完整交付作品。
- 1 次企业与教师联合验收。

采集证据：

- 试点协议或合作说明。
- 企业意向书/工单/验收单。
- 学生前后测与作品前后对比。
- 教师访谈与课程运行记录。
- 单条成本与周期台账。
- 真实发布账号及授权范围内的播放数据。

### 8.5 不可虚构的数据

以下内容没有凭证就填“待采集”，不能填入答辩 PPT：

- 试点学校数、学生数。
- 企业合作数和意向金额。
- 用户增长、留存和毛利。
- 播放量、转化率和收入。
- 软著、专利、商标状态。

## 9. 8 周执行计划

### 9.1 第一周：零故障底座

| 天 | 交付 |
|---|---|

| D2 | refresh token 自动刷新、登录页密码隔离 |

| D6 | 移动端学生工作台修复 |
| D7 | 断网彩排、两次连续完整演示、录屏 |

第一周出口条件：

- P0 代码风险清零。
- 断网启动成功。
- 3 次连续演示无失败。

### 9.2 第二周：视觉与产品体验

- 完成 3 组高质量场景资产。

- 分镜图上传、排序、替换流程可用。
- 移动端教师端与企业端抽检。
- 统一加载、空状态、错误和重试体验。

出口条件：

- 首屏 10 秒内能呈现作品价值。
- 成片无占位色块。
- 390px 宽度关键流程可用。

### 9.3 第三至四周：演示产品化

- 完成 Cached/Offline 场景包。
- Playwright 覆盖四角色 + 移动端。
- 加入依赖扫描、容器启动、E2E CI。
- 增加请求 ID 深链和基础可观测看板。
- 从教师端用量升级到管理员系统健康页。

出口条件：

- 10 次自动彩排通过率 100%。

### 9.6 角色分工

|---|---|---|

### 10.4 Go/No-Go 红线

出现以下任一情况，不进入正式主答辩：

- 最新成片仍出现纯色占位帧。
- 移动端关键页面不可操作。
- 健康检查在故障时仍返回 200。
- 公开注册仍可直接获得教师或企业权限。
- 演示密码出现在生产构建。
- 10 次彩排中有任意一次 P0 流程失败。
- 对外数据没有来源或授权。

### 11.2 演示纪律

- 主流程使用 Cached，不让评委等待模型随机延迟。
- 每个页面只讲一个结论，不逐字段解释。
- 生成前先展示结果，再回看过程。
- 不现场修改 Prompt、不临时换账号、不执行长任务。
- 所有点击在彩排中走过至少 10 次。
- 视频音量、浏览器缩放和投屏比例提前固定。

### 11.3 高频问答

| 问题 | 回答要点 |

| 这是不是套壳大模型？ | 展示编排器、版本链、成本日志、失败恢复、能力映射和评测，不是单 Prompt 页面 |
