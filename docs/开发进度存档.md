## 2026-10-16 · 极致优化轮：可靠性加固 + 性能提升（审计驱动的 9 项修复）

**背景**：全链路审计发现 1 个致命潜伏 bug（mock 掩盖）+ 5 处可靠性隐患 + 3 类性能问题，逐项修复并验证。

- **[致命修复] Edge-TTS 在 worker 中必崩**：原同步实现内部 `asyncio.run()`，在 arq worker 的事件循环中调用会抛 `RuntimeError: cannot be called from a running event loop`——真实配音/成片链路在 worker 里 100% 失败（此前测试全走 mock 未暴露）。TTS Provider 接口整体改 async（edge-tts 原生异步 + 行级重试 3 次退避；mock 用 to_thread 包 ffmpeg）。
- **[性能] TTS 逐行并行合成**：`asyncio.gather` + `Semaphore(TTS_CONCURRENCY=4)`，DB 写保持串行（AsyncSession 不可并发）。基准：12 行台词 4.61s → 1.40s，**加速 3.3x**（真实 websocket 场景收益更大）；worker 实测配音任务 0.30s 完成。
- **[性能] compose 阻塞调用下沉线程池**：`burn_video`/`placeholder_png`/`probe_duration_ms` 全部 `to_thread`，不再卡 worker 事件循环（max_jobs=4 并发才真正生效）。
- **[可靠性] LLM JSON 修复重试**：新增 `chat_json()`——首轮解析失败自动把坏输出喂回要求重排 JSON（usage 累计两次、成本如实记账）；`extract_json` 容错增强（代码块/尾随逗号/前后杂文/截断取首对象）；script/storyboard 的 max_tokens 4096→8192 防多集大纲截断。
- **[可靠性] 卡死任务清扫**：`sweep_stale_sessions` 把超时（默认 30 分钟）仍 running 的会话判失败 + 作品 generating→failed；三处触发（API 启动 lifespan / worker 启动 on_startup / 前端轮询惰性兜底）；worker 显式 max_tries=2。
- **[可靠性] 失败任务推进作品**：`finalize_work_from_session` 补 failed 分支（作品状态回落，不再永卡"生成中"）；`/agent-tasks` 响应增补 work_id。
- **[可靠性] 前端轮询加固**：useTaskPoll 增加 90s「处理缓慢」提示 + 10 分钟硬超时（明确提示检查 worker，不再无限静默轮询）；StepAudio/StepVideo 补失败/后台处理中/缓慢三种状态提示与刷新按钮。
- **[性能] N+1 查询清除**：提交列表 3N→3 条批量查询；`get_class_ability` 5N→2 条；能力均分/缓存更新 5→1 条（新增 `latest_scores_by_dimension(s)` 共享助手，tasks/orders/ability 三服务复用）。
- **[性能] 7 个热点索引**：works.created_by/task_id、agent_sessions.status、training_tasks.creator_id、work_reviews.teacher_id、work_orders.enterprise_id、order_bids.bidder_id（迁移 af9df446d338）。
- **质量**：prompt 语言策略明确化——剧名/角色名/台词按目标市场语言（北美→英文）、logline/大纲中文（供评审）；画面提示词要求角色外貌一致性；配音语言映射补 es-MX/ar-EG 音色（原会回退中文音色）。
- **验证**：pytest 36/36（新增 7 项优化专项）；真实 DeepSeek 复验（《The Comeback Waitress》英文剧名+英文台词+中文 logline，3 场景/集，5.9s，0.0095 元）；真实 worker 全链路（剧本→分镜→配音→字幕→成片 2592ms MP4）；Playwright 浏览器全流程 10 步回归全过。
